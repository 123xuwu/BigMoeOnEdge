# BigMoeOnEdge Android 版

手机应用：与一个比手机内存更大的混合专家（MoE）模型对话，权重从存储流式读取；
还可以把手机的硬件交给网络上的任意 OpenAI 兼容客户端使用。

它是 `bmoe-server` 的客户端，也就是桌面版运行的那个引擎进程
（[docs/application-framework.md](../../docs/application-framework.md)）。APK 把服务器作为
`libbmoe-server.so` 一同打包；一个前台服务用应用的数据目录在回环地址上启动它，
而应用的各个界面（聊天、模型、规划、设置，以及从设置进入的指标）通过 HTTP API
与它通信（[docs/server-api.md](../../docs/server-api.md)），行为与笔记本上的 Web 界面完全一致。
服务器作为独立进程存在，同时也构成崩溃隔离边界：导致引擎崩溃的驱动问题不会把应用一起带走。

除非打开 **在网络上提供服务**（Serve on the network），否则任何提示词或回答都不会离开手机。

即使离线，应用仍然需要网络权限：Android 把每个 IP 套接字都绑定到该权限，回环地址也不例外，
因此没有这个权限，应用就无法连接自己的引擎。离线本身没问题（回环接口始终存在，飞行模式也有）；
但被*拒绝*网络权限则不行。原生 Android 在安装时授予该权限，普通用户无法撤销，
但 GrapheneOS 的按应用 **网络** 开关和各类防火墙应用可以撤销。此时应用会在状态栏说明原因，
并提供一个跳转到系统设置的按钮；下载也会以同样的原因失败而不是反复重试；
不过模型仍然可以从文件导入。

## 安装

每个[发行版](https://github.com/Helldez/BigMoeOnEdge/releases/latest)都附带
`app-dev-release.apk`，它用项目固定的密钥签名，因此每个版本都能覆盖安装到上一个版本上。
从发行页下载后打开即可；Android 会询问一次是否允许从浏览器安装应用。
同一页面上的 `app-dev-debug.apk` 是用另一把密钥签名的调试构建：它无法更新 release 版。

## 构建

1. 交叉编译并暂存引擎二进制文件（需要 Android NDK）：

   ```powershell
   pwsh ../../scripts/build-android.ps1
   ```

   这一步会用 `libbmoe-server.so`（应用作为子进程启动的引擎）以及它所链接的
   `libllama`/`libggml` 共享库填充 `app/src/main/jniLibs/arm64-v8a/`。
   `libbmoe-cli.so` 也会一并暂存在旁边，但应用不会启动它。

   release 构建额外包含 Hexagon、Vulkan 和 OpenCL 后端。它在上游的 Snapdragon 工具链容器中运行
   （容器自带 Hexagon SDK；Vulkan 和 OpenCL 所需的东西由 `scripts/android-gpu-deps.sh` 拉取），
   然后以同样的方式暂存：

   ```bash
   docker run --rm -v <repo>:/workspace ghcr.io/snapdragon-toolchain/arm64-android:v0.7 \
       bash /workspace/scripts/build-hexagon-android.sh
   powershell -File ../../scripts/stage-hexagon-jnilibs.ps1
   ```

   release APK 由 CI 用这种方式构建，为后端支持的每一代 NPU（v73 到 v81）附带对应 skel，
   并包含两种 GPU 后端，因此一个 APK 就能适配所有手机，规划器会测量手机实际拥有哪些设备。
   用 `build-android.ps1` 本地构建的 APK 只有 CPU。

2. 构建并安装 APK。用 Android Studio 打开本目录，或直接使用仓库内的 Gradle wrapper。
   应用有两个发布风味（见下文）；按需构建其中一个：

   ```bash
   ./gradlew assembleDevDebug
   adb install app/build/outputs/apk/dev/debug/app-dev-debug.apk
   ```

   应用的纯 Kotlin 逻辑（事件流解析器、聊天协议、参数表、设置表单、目录状态、
   合并后的模型列表、规划中的数字、上下文警告、由对话事件构建的转录、
   “再次回答”、对话的 JSON 结构，以及应用过去保存在手机上的对话的一次性迁移）
   在 `app/src/test` 下有 JVM 单元测试；CI 会运行它们，`./gradlew testDevDebugUnitTest` 也一样。

   对外发布的旁加载构建改用固定密钥签名，因此更新会覆盖安装上一个版本，而不是被拒绝。
   这需要在 `app/` 旁边有一个 `keystore.properties`（已被 gitignore）；
   没有它时，构建会回退到调试签名。GitHub release 附带的 APK 由 `release-apk` 工作流
   从该 tag 的干净检出构建。

## 风味（Flavors）

两个构建风味的差别只在于模型如何到达设备：

- **dev** —— 旁加载（CI 附加到 release 的就是这个）。保留全文件访问权限，
  因此也能读取通过 adb 推送到共享存储的模型。应用 ID 为 `….example.dev`。
- **play** —— 符合 Play 商店规范。没有宽泛的存储权限：模型只能通过应用内下载器或文件选择器获得。
  构建命令：`./gradlew assemblePlayDebug`。

两者都声明 `android:appCategory="game"`。这是一个性能决策，并不表示应用本身是什么：
厂商的性能层会读取该属性来选择 CPU 调度档位，在 OxygenOS 测试设备上，
它把前台频率上限从 1.9/1.65 GHz 提升到硬件最大值的 3.32/3.80 GHz。
解码是手机除游戏之外最吃 CPU 的操作。该效果来自厂商而非 Android 本身，
所以任何数字都应按单台设备的实测结果看待。

## 把模型放到设备上

模型界面只有一份列表，即 **你的模型**（Your models）：引擎看到的内容和目录提供的内容
按文件合并，因此目录下载的模型只占一行（见 `docs/screens.md` 的“Models”）。
每一行只有一个状态和对应的一个操作：可用（下载）、下载中（进度和取消）、
部分下载（继续、删除部分文件）、在本机（加载）、已加载（重新加载、卸载、前往聊天）、
分片缺失（下载，适用于还有剩余条目的情况）。删除会移除模型的文件，
分片集作为一个整体处理，并会先询问（服务器在其模型目录内删除，应用在其他可写位置删除）；
忘记则把从仓库或链接添加的条目从列表中移除，但保留其文件。
手机上什么也没有的目录条目会作为建议列在底部；
不是模型的文件（如投影器、草稿头，按文件头判断）单独列出，没有加载按钮。
手机上没有任何模型时，界面显示三个步骤（找到模型、确认装得下、下载再加载），
此时应用会直接打开该界面，而不是空的聊天界面。

列表覆盖引擎自己的目录（应用内部存储，应用内下载和导入都落在这里），
以及模型在手机上可能存在的其他位置——应用在启动时把这些交给服务器（`--scan-dir`：
应用的外部文件目录，以及 dev 风味下的 `/data/local/tmp/bmoe` 和 Downloads），
以及各自直接包含的子文件夹；界面底部有一节 **模型存放位置**（Where models live）会列出它们。
服务器负责把分片集归组、读取每个模型的架构、说明本构建是否支持对其流式加载，以及该文件到底是不是模型；
应用自己不读取任何 gguf。除最后一个方式外，下面这些都不需要存储权限。

1. **内置目录**（两种风味都有）：本引擎实测过的模型，点一下即可。
   目录是项目唯一的数据文件 `catalog/models.json`，打包进 APK 并由服务器读取；
   应用自己完成传输（手机上没有 `curl` 可供服务器调用），由一个前台 worker 执行，
   即使应用被杀也能存活，并能续传中断的传输。它的通知像列表行一样显示进度。
   如果目录行给了 `sha256`，文件在校验通过后才会成为模型；不匹配则删除下载并说明原因。
   文件名不是单纯文件名的条目不会提供。

2. **来自 Hugging Face**：输入模型名、仓库 id 或其 URL，分四步展示：
   查找（Find）、选择（Pick）、检查（Check，服务器在下载前先读取文件头，并给出结论，
   卡片以该结论作为标题，颜色取自服务器的返回码）、下载（Download，模型会变成目录条目，
   其“你的模型”行承载下载）。

3. **任意其他模型**：粘贴一个指向 gguf 的直接 https 链接，或分片集的任意一个分片。
   服务器把它变成目录条目（`POST /api/models/url`），应用像对待任何条目一样下载其文件，
   支持续传，并对整个分片集显示一个进度条。手机上的服务器没有 `curl`，
   无法向主机询问文件大小，因此大小留空，文件到达后即计为完整。
   下载前不会检查链接，所以指向空内容的链接会立刻结束，并在行内显示主机的应答
   （明确的 `4xx` 永不重试）。服务器拒绝的链接会显示拒绝原因。
   也可以选择一个设备上已有的 `.gguf` 进行导入。

4. **adb push**（仅 dev 风味，需要全文件访问权限，dev 构建会在刷新时申请）：

   ```bash
   adb push Qwen3-30B-A3B-Q4_K_M.gguf /data/local/tmp/bmoe/   # 真实文件系统：O_DIRECT 可用
   adb push Qwen3-30B-A3B-Q4_K_M.gguf /sdcard/Download/        # 模拟存储：缓冲 I/O
   ```

应用内下载和导入落在真实的 f2fs/ext4 卷上，因此流式专家读取能以 O_DIRECT 全速进行；
从模拟的外部目录读取模型会回退到缓冲 I/O。下载需要等于模型大小的空闲空间，不会产生临时第二份拷贝。

**续传。** 下载写入 `<name>.part`，完整后再重命名，因此中断的下载会保留已有字节。
连接中断会自动带退避重试，每次尝试都通过 `Range` 请求从 `.part` 继续；
如果主机返回明确的 `4xx`（文件不存在、需要 token），下载立即结束，原因显示在行内。
无论是什么原因停下来（重试用尽、你按了 **取消**、应用或手机重启），
该行都会显示 **继续（X / Y GB）**，并带出磁盘上已有的字节数，按下即从该处继续；
空闲空间检查只计算仍需下载的字节数。同一行的 **删除部分下载** 是唯一会丢弃这些字节的操作
（服务器只在其模型目录内删除该条目的 `.part` 文件）。桌面 Web 界面的措辞和行为也是如此
（`docs/server-api.md`，“Models”）。旧版构建自行下载、没有条目的链接没有可续传的行，
因此其 **取消** 会删除它的部分文件。

### 分片模型（gpt-oss-120b、DeepSeek V4 Flash、Qwen3.8-Flash-Next）

超过 Hugging Face 单文件 50 GB 上限的模型会以多个分片文件发布
（`-00001-of-0000N.gguf`）。引擎原生支持分片集：仓库列表按第一个分片把整个集合显示为一个模型，
分片逐个下载（每个都可续传），列表中对该集合显示一个进度条，
模型列表也按第一个分片只提供一次该集合——引擎打开的就是这个文件。
对于 adb 推送的模型，要把每个分片都推到同一目录。注意空间：
DeepSeek V4 Flash UD-IQ2_M 在磁盘上约 91 GB，
Qwen3.8-Flash-Next UD-IQ3_XXS 约 82 GB，其 Q2_K 构建约 80 GB。

Qwen3.8-Flash-Next 需要在设置中选择 **Dense 权重 = pinned**（pinned、dma-buf）。
它的 dense 部分有 4.3 GB，每个 token 都要遍历它：设为 `anon` 时内核会把它换出到 zram，
单个 token 会卡住 10–20 秒；设为 `mmap` 时每个 token 都要从闪存重新缺页读入。
它 51B 的 n-gram 表会被自动保留，无论该设置如何都保持 mmap。
规划器会尽可能地这样选择；目录里的 Q2_K 构建 dense 部分只有 2.4 GB，
相当于能让专家缓存多拿回约 2 GB。

## 加载与规划

模型界面上的 **加载**（Load）会打开模型。若 **每次加载前先规划**（Plan before every load）开启
（位于规划界面，默认开启），引擎会先测量手机（存储读取速率、可持有并锁定的内存、
逐个单独进程测量的每个计算设备），为该模型选择流式加载参数，然后加载。
规划界面首先说明是为哪个模型规划的（“For <文件名>”：若已规划则为规划的模型，
否则为一次加载会打开的模型，旁边有 **更改** 链接到模型界面），
然后用一句话给出规划的决定、机器情况、由哪个设备处理提示词、哪个处理 token，以及三个数字：
预期的解码速度，以及首次回答后的实测值与其差值；规划所信任的缓存命中率与实测值；
进程持有的内存与允许持有的内存。无论当前在哪个界面，
应用都会在会话打开时和回答结束时读取规划，因此你查看时数字已经就绪。
Apply（应用）和 Measure again（重新测量）位于数字下方（顶部的错误也有自己的“重新测量”）；
应用会列出它更改的设置，每项都链接到设置中的对应行。
再往下是内存的去向、每个计算设备做什么及其原因，以及分组后的决定，
每条都带有支撑它的事实和指向相应设置的链接。
复制诊断信息（Copy diagnostic）会把命令和规划器的完整说明放入剪贴板，便于提交问题报告。
界面会显示当前正在进行测量的哪个阶段；你自己在设置中设定的值永远不会被覆盖。
若未加载模型且没有已测量的规划，则显示上次应用规划后设置所携带的决定。
模型在空闲十分钟后被卸载，把内存还给手机；下一条消息会重新加载它。

导航栏上方的状态栏在所有界面都会显示引擎正在做什么，并显示正在进行的下载
（如“正在下载 42%”，或“2 项下载 42%”），点击可前往模型界面。
当开启“在网络上提供服务”，或某次请求因上下文不足被拒绝后，
已加载模型若上下文低于编程智能体首次请求所需，其下方会出现警告：
包含当前上下文、服务器建议值、更大上下文会占用专家缓存内存的提示、
指向提高该设置的链接，以及一个 ✕ 可对该模型和上下文关闭它（再次被拒绝时会重新出现）。
同一行也会一直显示在设置中的“在网络上提供服务”下方。因上下文占满而被拒绝的聊天，
会在“新对话”旁提供同样的链接。该数字和设置来自服务器（`model.ctx_advice`）。

## 聊天

应用以 `--chat-only` 启动其服务器：对话由引擎进程持有
（[docs/agent.md](../../docs/agent.md)），而不是由应用持有，
因此应用在后台时回答仍会继续，同一个对话对手机服务器的任何客户端都可见，
但它们只是普通聊天，没有工具、工作区和任务。智能体属于桌面端：
手机上的小模型还不足以承担这一角色。抽屉按从新到旧列出对话，
正在回答的那个会带标记；某一行的菜单可以重命名或删除。

- **转录。** 你的消息在右侧；长按可复制，或编辑后重新发送（其后的内容全部丢弃）。
  模型的回答以 GitHub 风格 Markdown 显示
  （表格有边框，过宽时可横向滚动，由 multiplatform-markdown-renderer 使用应用的设计令牌绘制；
  不加载图片，不执行 HTML），其思考过程折叠在上方；
  每条下方有复制，最后一条下方有 **再次回答**（Answer again），会把最后一个问题按原样再发一次
  （服务器会丢弃旧回答）。若有事情没有发生，会用文字说明原因。停止会终止回答。
- **输入框。** 提示词、发送，回答生成中则显示停止；提示词旁的 + 包含
  **从选项中选**（Choose from options，见下）。未加载模型时，空白聊天界面会提示从模型界面加载一个。

较早版本保存在手机上的对话会在第一次成功连接服务器的启动时一次性交给服务器：
每个都变成带消息的服务器对话，只有服务器的回答表明所有消息都已到达后，
手机上的副本才会被删除（忽略这些消息的旧版服务器不保留任何内容，手机则保留副本）。

## 外观

石板灰与青色，明暗跟随系统，Material 3，8 dp 圆角、1 dp 线条、卡片带柔和阴影。
颜色值集中在一处，`ui/Theme.kt`（`LightTokens`、`DarkTokens`），并映射到 Material 的颜色角色。
正文使用 Inter，代码使用 JetBrains Mono，静态字重实例打包在 `res/font` 中，
两者都遵循 SIL 开放字体许可（许可文本在 `THIRD_PARTY_LICENSES` 中，并随 APK 分发）。
像素风 logo 是唯一保持自身风格的标识。

## 设置

所有引擎可调项都来自引擎的参数表（`GET /api/params`）：分组、行、取值范围和帮助文本。
应用不命名其中任何一项，因此引擎新增的旋钮无需改应用就会出现在这里，
同一设置与桌面端的含义也一致。页面按分组一个卡片，顺序同参数表，
每组带一行帮助；所有卡片默认折叠，按参数表顺序列出表中标记为表单的项（`form`；
不发送该字段的服务器则提供其基础行），与 Web 界面和 iOS 应用显示的行相同。
你设定的每个值，无论是否在表单上，都改放在分组之前的 **由你设定**（Set by you）卡片中，
卡片标题显示数量，未设定任何值时隐藏：每行在页面上只出现一次，
重置会把它送回所属分组，指向你设定值的链接会打开该卡片。
其余参数仍归引擎所有，由命令行或 API 设定。每行有一个标签表示其值的来源
（默认、来自规划、由你设定）；你设定的值可以重置，或在规划决定了另一值时替换为
**使用规划值**（Use plan value）。**重置我的所有设定**（Reset all my values）会在询问后移除你的设定，
保留引擎启动时的值和模型。数字会显示单位、特殊值的名称和常见范围。
“需要重新加载”只标记与已加载模型不同的行，并会有横幅提供重新加载。
从规划界面或上下文警告中的链接会定位到对应行。

**在网络上提供服务**（Serve on the network）是页面上的第一个卡片，与其他卡片一样折叠，
即使关闭其标题也显示状态：关闭、开启并显示手机地址、或已开启但不在网络上。
开启后，引擎监听所有接口，卡片显示手机在 Wi-Fi 或以太网上的地址
（`http://<手机 IP>:8765`，可一键复制，网络变化时自动更新）、
API 密钥（默认遮蔽，带显示、复制和新建密钥）以及客户端应使用的基地址
`http://<手机 IP>:8765/v1`。任何 OpenAI 兼容客户端都可以用
`Authorization: Bearer <key>` 访问它：笔记本上的编程智能体、Open WebUI、脚本等。
提示词和回答以未加密方式经过网络，卡片中也有说明；请只在可信网络上使用。
编程智能体需要比聊天更大的上下文：它首次请求就约 10k token，
因此在把智能体指向手机前，应把上下文设为 16384 或更大，代价是占用专家缓存
（见[为客户端设定上下文](../../docs/server-api.md#sizing-the-context-for-a-client)）；
卡片会显示上下文警告及其“提高”按钮。修改上下文会重启引擎，
之前已加载的模型会在引擎恢复后重新加载。

即使不对外共享，引擎也要求密钥：在手机上，回环地址对每个已安装应用都可达，
开放的服务器会让任何应用从事件流中读取对话。
应用每次启动都会用随机密钥启动引擎，写入其私有存储中只有它能读的文件
（`--api-key-file`，权限 0600，绝不出现在命令行上），并在每次请求中发送；
共享时，密钥是设置中显示的持久密钥，因此客户端重启后仍可用。
在信任该端口上的服务器之前，应用会先验证它就是自己启动的那个：
自己启动的服务器会拒绝随机密钥、接受本次启动的密钥。
端口 8765 上其他程序的服务器（开放的，或自带密钥的）会被报告为占用了端口，并且不会向它发送任何内容。
服务器的停止和重启在一个后台线程中逐步执行，因此重启永远不会与旧进程争抢端口，
停止也绝不会冻结界面；已停止服务器迟到的退出报告不会改变任何状态。
事件流有看门狗：服务器每 15 秒 ping 一次，连续两次 ping 都静默的流会被重连。

**外观**（Appearance）卡片紧跟 **在网络上提供服务**，同样折叠：

- **主题**：系统、浅色或深色（与 Web 界面相同）。
  系统跟随手机；选择立即生效，包括状态栏和导航栏。
- **指标**（Metrics，默认关闭）：为每个已加载模型记录一个逐 token 的 CSV 文件。
  开启期间，设置中会出现 **指标** 入口，打开指标界面；返回则回到设置。

接下来是引擎相关的卡片，最后是折叠的 **本应用**（This app）卡片，含停止和启动引擎，结束整个页面。

预填充设备（`prefill-device`）也是一行普通设置，由规划器选择：
它会在预填充的宽大矩阵乘上测量构建所包含的每个计算设备
（经 Vulkan 或 OpenCL 的 GPU，经 Hexagon 的高通 NPU，release APK 三者皆有），并启用最快的那个，
仅用于预填充；解码仍留在 CPU 核心上。规划界面会说明它选择了哪个以及原因。
应用里没有任何地方写死设备名。见 `../../docs/npu-prefill.md`。

## 指标

指标界面在 **指标** 开启时从设置进入，显示当前或上一次生成的实时卡片
（速率，以及每个 token 的时间拆分为计算、闪存等待、缓存管理和其他未归属部分），
然后是 CSV 文件：查看、分享、关联其各列，或在同一坐标轴上比较两个文件。
回答流式输出时，聊天界面会在提示词上方用一行显示同样的速率。
闪存项以及 CPU 数字所用的线程数来自服务器（`flash_wait_ms`、`compute_threads`、`busy_threads`），
绝不从设置中读取。各字段在 `../../docs/telemetry.md` 和界面的术语表中说明，
其中设置部分来自引擎的参数表：记录文件时使用的每个设置都按参数表中的标签显示，
带类型和单位；一次运行的标识会列出所有影响回复且非默认值的设置。

## 预期数字

在 UFS 4.x 存储、约 12 GB 内存的手机上，以 4000 MiB 专家缓存、4 条 I/O 通道、
4 个计算线程流式加载 Qwen3-30B-A3B-Q4_K_M，解码稳定在约 **0.55–0.6 秒/token（约 1.8 tok/s）**，
模型约为设备内存的 1.7 倍，且无损。方法与缓存/线程扫描见 `../../docs/benchmark-method.md`；
跨模型的表格见 `../../README.md`。

## 从选项中选

提示词旁的 + 菜单中的 **从选项中选**（Choose from options）会把提示词变成一个问题，
并增加一个选项输入框，每行一个选项。

模型不写回答而直接选一个：选项被编号，整个请求是一次预填充、没有解码
（`POST /api/decide`），每个选项返回模型给它的概率
（不必然加总为 100%；剩余部分是模型的不确定）。一次决定不是一轮对话：
其结果会留在聊天界面直到关闭，永远不会发送到服务器的对话中。
引擎侧见 [docs/decide.md](../../docs/decide.md)。
